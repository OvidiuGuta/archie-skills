# `/archie-agent`

User-callable, and the **persona**: `/archie-agent <name> [request]` makes a session one of your Archie Agents. It reads the Agent with the Archie MCP server's `get_agent`, by name and ignoring case, takes on its instructions exactly as they stand in Archie, and passes the Agent's name as `agent` on every Archie call the session makes, its helpers' calls included, so the whole run is signed as that Agent. What follows the name is your request, such as a Task key; with none, and instructions that ask for nothing, it greets you and waits. It has no behaviour of its own: what the Agent does is its instructions, which you edit in Archie's Settings, so an edit there changes the next session with no skill change. An unknown or inactive name, or no connected Archie MCP server, stops it with one line, so a typo never runs a session as Archie by accident. The workflow skills carry no persona, so the two compose: a workflow skill named in the Agent's instructions, or beside `/archie-agent` in the prompt, runs as that Agent, and one run without it acts as Archie. See ADR-0117 in the archie repo.
