# `/archie-pr`

Model-invoked, and the one writer of a PR's title and body in a repo set up for Archie — one whose `AGENTS.md` carries a `## Project facts` section or that has an `.archie/` folder. [`/archie-implement`](../../skills/archie-implement/SKILL.md) dispatches it to open an Epic run's draft PR, and [`/archie-review`](../../skills/archie-review/SKILL.md) dispatches it after every fix round, so the body always describes the diff a reviewer is approving: a refresh rewrites the title and body whole with `gh pr edit` ([ADR 0025](../../docs/adr/0025-a-pr-is-written-by-one-skill.md)). It owns the title, from the repo's PR conventions, and the body. Draft or ready is the caller's word, and rebasing is left to the user.

The body has three sections and no preamble, in the repo's own language from `CONTEXT.md`. **Summary** is the smallest view that makes the change clear — pseudocode, a call tree, a component tree, a shallow file tree or Mermaid, drawn as a `diff` when the shape already exists. **Evidence** is a before and after per outcome: collected first from each Task's `## Proof` and the session's test runs and screenshots, and produced only when missing, the before by running the new tests against the base. Screenshots are linked from a home the PR can reach: an Asset on the Task in Archie, the leaf's `.archie/` directory on files, and none at all for an ad-hoc PR, which falls back to test runs. **Merge Danger** names the **Door**, one-way or two-way, and the **Blast Radius** in one word, then what could break, including any criterion no test reached and nobody walked. The hand-test walkthrough stays in the session report.

## Archie mode

In a bound folder screenshots are uploaded as Assets on the Task they prove, or on the Epic for a leaf-wide outcome, and the glossary is the Project's term Notes. It acts as the Agent whose description in the `guide` Index fits building, or as the Task's assignee when that is an Agent.
