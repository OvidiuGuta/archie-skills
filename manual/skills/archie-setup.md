# `/archie-setup`

User-callable. Records this repo's facts in `AGENTS.md`, makes sure a `CLAUDE.md` imports them, and keeps `.archie/` out of the ignore file so planning is committed. It explores, shows the draft, and writes only once the user has confirmed it; a fact it cannot read out of the repo is a direct question, answered with a value or with *remove*, so no placeholder is ever written. Re-running rewrites the delimited facts block and leaves the rest of `AGENTS.md` untouched. It then dispatches [`/archie-standards`](../../skills/archie-standards/SKILL.md) to seed `STANDARDS.md` from the baseline — the rules `/archie-review` checks against and `/archie-tdd` builds to ([ADR 0020](../../docs/adr/0020-standards-md-is-the-review-control-surface.md)) — named in the same confirmation as everything else, written by the skill that owns that file rather than by setup, and merged into whatever standards the repo already carries.

## Archie mode

Setup is where a folder chooses its mode, so its confirmation message opens with the question: files, or Archie? Choosing Archie asks for the Project's Key, made in the web app with its Agents and Role map, and before anything is written setup calls `guide {projectKey}` to confirm the Project and show that map, so a mistyped Key or an unmapped Role is caught here. When no Archie MCP server is connected, it gives the Claude Code and Codex lines inline and points at [the connection page](../connecting.md), then checks again. The binding line is the first line of the facts block and a re-run on files mode drops it. `STANDARDS.md` and the facts are recorded the same way in both modes, and an existing `.archie/`, `docs/adr/` or `CONTEXT.md` is left for the human. It carries the `Where the tree lives` block as `architect`.
