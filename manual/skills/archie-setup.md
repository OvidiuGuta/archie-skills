# `/archie-setup`

User-callable. Records this repo's facts in `AGENTS.md`, makes sure a `CLAUDE.md` imports them, and keeps `.archie/` out of the ignore file so planning is committed. It explores, shows the draft, and writes only once the user has confirmed it; a fact it cannot read out of the repo is a direct question, answered with a value or with *remove*, so no placeholder is ever written. The facts are a plain `## Project facts` section with no markers, and a re-run finds it by its heading and replaces it, leaving the rest of `AGENTS.md` untouched. It then dispatches [`/archie-standards`](../../skills/archie-standards/SKILL.md) to seed `STANDARDS.md` from the baseline — the rules `/archie-review` checks against and `/archie-tdd` builds to ([ADR 0020](../../docs/adr/0020-standards-md-is-the-review-control-surface.md)) — named in the same confirmation as everything else, written by the skill that owns that file rather than by setup, and merged into whatever standards the repo already carries. Facts and standards are recorded the same way in both modes.

## Archie mode

Setup reads the mode the way every skill does, from the folder's `origin` remote, and its confirmation opens with the mode and what decided it: the Project the remote matched, or files mode because no Project names the remote, there is no `origin`, or no Archie server is connected. A remote no Project names comes with the one step that binds it: add the repo in the Project's settings, then re-run. With no server connected, it gives the Claude Code and Codex lines inline and points at [the connection page](../connecting.md).

In Archie it reports how the skills will find their way in the human's flows. Its [needs list](../../skills/archie-setup/references/bindings.md) names a Type for an Epic, a Task and a leaf's closing Task, a Status whose `Next:` line names each of `/archie-scope`, `/archie-to-spec`, `/archie-design`, `/archie-to-tasks`, `/archie-implement` and `/archie-review`, a Label for decisions and one for terms, and an Agent for planning, building and reviewing. Setup walks it against the `guide` Index, reading each Type's Workflow through `get_workflow`, so a flow with no Tasks yet is checked too. Each need shows the row it binds to, and every gap or several fitting rows carries a proposed name, Status group where it applies and description for the human to create in Settings. Setup writes nothing in Archie and keeps no binding, so re-running it after editing the flows checks them afresh.

No binding is written into the repo. An `**Archie Project:**` line or `archie:facts` markers from an older setup stay where they are unless the user agrees to remove them. An existing `.archie/`, `docs/adr/` or `CONTEXT.md` is left for the human. It carries the `Where the tree lives` block, choosing its Agent by planning.
