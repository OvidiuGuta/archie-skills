# `/archie-review`

User-callable, and the review phase, also run unattended by [`/archie-implement`](../../skills/archie-implement/SKILL.md) on the draft PR an Epic run opens. Takes a PR, the current branch (diffed from its merge-base with `main`), or an Epic reference — the Epic adds the contracts, `spec.md` and the task files, which is what turns the **Spec** axis on; without one that axis is skipped and the header says so. Two parallel axis sub-agents that never see each other's findings, both read-only: they run commands, including the suite, and write no files. **Spec** judges the diff against the user stories and acceptance criteria, with `## Implementation Decisions` and `## Testing Decisions` read as context rather than contract. Every finding carries a quoted contract line **and** a named failure — the path through the diff and what happens there instead — and the leaf's tests are its instrument: a criterion covered by a passing test is silence, one whose test fails is the strongest finding it can make ([ADR 0021](../../docs/adr/0021-the-review-fixes-what-it-finds.md)). It reads each task file's `Integration:` line too, so a correctly-deferred tracer bullet is not flagged for owing no seam test. **Standards** grades against the repo's own `STANDARDS.md`, plus the **test rules** and the **secrets** check, which are all that hold whatever the repo documents, seeded by [`/archie-setup`](../../skills/archie-setup/SKILL.md) and the user's to edit or delete from the moment they land ([ADR 0020](../../docs/adr/0020-standards-md-is-the-review-control-surface.md)) — a rule they remove is a rule this review stops checking, which is the point — and it marks 🔴 only the secrets check, the test rules, or a clear breach of a yes-or-no rule in `STANDARDS.md`; a rule under a heading ending `— judgement calls` is named and quoted rather than reported as a breach, always 🟠. Severity sits on the finding, **🔴** a blocker or **🟠** a **Suggestion**, and only a 🔴 moves the **grade**, which has two tiers per axis and overall: 🔴 `needs work` while any 🔴 stands, 🟢 `mergeable` otherwise, Suggestions or not ([ADR 0024](../../docs/adr/0024-a-review-converges.md)). Before any 🔴 reaches the report it passes the **blocker check**: once both axes return, and only when one raised a 🔴, a single read-only verifier sub-agent is handed each 🔴's claim, quoted line and named failure — no Suggestions and none of the axes' reasoning, so it judges on evidence rather than agreeing with the argument. It reads the code, may run the suite, writes no files, and confirms or drops each one with a one-line why. A dropped 🔴 leaves the Blockers and the grade, and is listed under **Unconfirmed** with that why, not demoted to a Suggestion; the verify pass after a fix does not run the check again. The report is a grade header, then **Blockers** above **Suggestions** above **Earlier findings** above **Unconfirmed**, each finding tagged `[spec]`, `[standards]` or `[pr]` with its file and line; an empty list is left out, so a first review with no findings is the header alone, and what passed is silence. Then it halts, whatever the grade, and the user picks which findings to act on — those go to one `/archie-tdd` engineer as **exit criteria**, the complete list of what must be true once the fix lands, each entry a `file:line`, the behaviour expected there and what proves it. The orchestrator verifies that fix read-only against the criteria it wrote, plus the fix diff at a blocker bar of secrets and 🔴 breaches only, and re-issues the grade. **One round**: findings that survive halt the run for the user to read, because a round the fix could not settle means the contract is the problem. The tree is left dirty with the commit offered, and a review with no findings, or whose findings the user declines, leaves it exactly as it arrived.

**A re-review remembers.** Nothing about a review reaches disk: its memory is the PR's conversation — earlier reports and GitHub reviews, the user's general comments and inline threads, read through `gh` — or, when the PR holds no earlier review, a report issued earlier in the same session. With either, the review is a **re-review**, and both axes are also handed a re-review brief: every earlier finding on their axis is carried forward under **Earlier findings** in its original wording as resolved, still open or dismissed, and a new 🔴 may sit only on a line changed since the commit the earlier review saw, so code passed once is not blocked the next time. A still-open earlier 🔴 still holds the grade. After the axes, the orchestrator sweeps the user's own PR comments and lists each open one that no finding answers as a `[pr]` finding — 🔴 for a requested change, 🟠 for a question or remark. The blocker check sees only new 🔴s from the axes, and on a re-review also drops one off the changed lines; a `[pr]` 🔴 is the user's word and a still-open one was checked when first raised, so neither goes through it. With no memory the review runs in full and its header says `not a re-review`. Outside an Epic run the report goes on the PR only on the user's word — offered when they decline the fix round and again after the verify pass — and posting it is how they carry memory into a later session ([ADR 0024](../../docs/adr/0024-a-review-converges.md)).

**Unattended**, from an Epic run, nobody picks: the report goes on the PR as a comment, and the review **triages** the findings itself, dropping only the **wrong** ones — a misquoted contract line, a failure that cannot happen, or a demand no contract or standard makes — and fixing every other finding, 🔴 and 🟠. It commits the fix as `<reference>: review fixes`, pushes, and posts a second comment with the re-grade and **Fixed**, **Surviving** and **Dropped**, each drop with its reason ([ADR 0023](../../docs/adr/0023-an-epic-run-ends-reviewed-and-every-criterion-is-proven.md)).

## Archie mode

In a bound folder the Epic reference is the leaf's key, and a `3.2` is refused. The Spec sub-agent is handed the Spec and the Task bodies as text, with the leaf's closing Task named as such since the briefing reads `Integration:` lines. The Standards axis is unchanged: `STANDARDS.md` and the other standards files stay on disk. It acts as the Agent whose description in the `guide` Index fits reviewing, or as the Task's assignee when that is an Agent.
