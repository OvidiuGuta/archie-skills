# `/archie-verify`

The closing Task of a leaf Epic, reached by `/archie-implement` and typeable by name. Every other Task in the leaf **defers integration** ([ADR 0019](../../docs/adr/0019-integration-is-one-closing-task-per-leaf.md)), so this is where the leaf's integration tests get written — once, at the seam [`/archie-design`](../../skills/archie-design/SKILL.md) settled, against a feature that is finished. That is what the deferral buys: a CRUD leaf can seed and tear down through its own delete, where a test written at Task two had nothing to clean up with. It reads the Spec's `User Stories` as the **claim**, the task files for what each Task landed, and the tests already on that seam — which are both the house style and, often, coverage it is about to duplicate. Per story the honest answer is a new test, several, an edit to an existing one, or nothing where one already covers it. Because the code exists first, a passing test proves nothing on its own, so every test it writes **proves it can fail**: flip the expected value, watch it go red, flip it back. A red test is then one of two things, and telling them apart is the whole judgement: a **bug** — built and wrong — is fixed inline with the red test standing in for the outer loop and a unit test on each unit the fix modifies; a **gap** — never built, because a Task missed a story — is left alone and reported, since building it here would land a feature with no Task, no criteria and no review. It then runs the repo's gates and reports concisely: what it added, what no test reaches (which becomes the leaf-level walkthrough), the gaps, and the gate results. A leaf whose Spec marked the seam not-applicable has no closing Task at all, which is how a repo with no integration harness opts out.
