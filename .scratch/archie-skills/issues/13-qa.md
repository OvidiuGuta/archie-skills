# 13 — `/qa`

**What to build:** The sub-agent skill that proves a Task's demoable outcome against the running app, and reports honestly about what it could not prove.

**Blocked by:** 01 — Conventions and templates.

**Status:** ready-for-review

- [x] Model-invocable, spawned by `/implement`'s orchestrator
- [x] Reads the `AGENTS.md` facts section to start the real app, with its port, seed data and test credentials
- [x] If the run command is `unknown`, asks the user rather than guessing at a conventional one
- [x] Writes exactly one Playwright journey test per Task, walking the demoable outcome front to back and asserting the criteria on that path
- [x] Adds a second journey only when the Task genuinely has two distinct user paths, and notes that this usually means it should have been two Tasks
- [x] Reports each acceptance criterion as one of three outcomes: pinned in the journey test, verified but not pinned, or unverified because nothing observable could confirm it
- [x] For a `ready-for-human` Task, verifies observable state instead: an env var is present, a key authenticates, an account exists, and writes no journey test
- [x] Returns findings and does not fix them
- [x] Ships `agents/openai.yaml`, and `README.md` documents the skill
